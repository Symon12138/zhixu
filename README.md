# 知序 · AI 领学工作台

面向个人使用的中文 AI 领学网页：你给学习目标和材料，由导师安排路径、逐步讲清机制、接住卡点，适时安排练习与复盘。书架、笔记与进度用于辅助学习，不要求使用者先自行排课程；AI 也不能替你作答后宣称你已学会。不是 Gemini 官方产品，不承诺与某个模型的教学效果完全一致。

## 与最初目标对照

- 原始目标是做一个中文学习网页，尽量接近 Gemini 的“学习模式”。当前产品保留这条主线：用户只给目标与材料，AI 导师安排路线、逐步讲解、追问、复盘并维护真实理解证据；书籍、笔记、复习、诊断和跨设备同步都是围绕这条主线的支撑能力。
- 产品不承诺与 Gemini 完全一致或绝对准确。已实现 50 个测试文件、577 项工程回归（最近一次全量 `npm test` 为 0 失败）、跨学科 9 场景连续两轮真实模型评测、多回合插问/恢复、数值闸门、自动搜索供应商链与指定网页逐字引文核验，但这些仍是固定剧本与结构约束，不能替代人工事实审核。
- 运行时主模型与独立评审模型已设为当前最高档思考 `high`；子代理实现模型与应用运行时模型相互独立，不影响线上选择。
- 当前边界仍清楚：自动搜索默认关闭，需在服务端开启 `ZHIXU_WEB_SEARCH`；开启后若未设置 `ZHIXU_SEARCH_ORDER`，内置顺序默认以 You.com 免费接口（无需 Key）为先并继续尝试其它已配置供应商；登录用户也可自带个人搜索配置。不做扫描 PDF OCR、不支持多实例高可用、不声称法律/医疗/金融等高风险领域权威。

## 运行

需要 Node.js 22.13+（应用使用原生 Promise.withResolvers；本地 PDF.js 构建依赖要求此版本）。

```bash
npm install
npm run dev
```

打开 **http://127.0.0.1:5173**。开发命令同时启动 Vite 前端和 `127.0.0.1:3001` 的 API 服务。

`npm run check` 执行 TypeScript 检查，`npm test` 运行 50 个测试文件（教学状态、账户隔离、工作区同步、诊断、复习、迁移、备份、服务端个人凭据、云端书架与同步、前端懒加载、部署静态配置等），`npm run build` 执行 TypeScript 项目构建与 Vite 生产构建。**运行测试需要 Node.js 22.15+**（`tests/markdown.test.ts` 使用 `module.registerHooks`）；应用本身在 22.13+ 可运行。

`npm start` 是**公网生产入口**，会强制要求 HTTPS 公网来源和 Secure Cookie；反向代理信任配置（`ZHIXU_TRUST_PROXY=true`）由 `npm run check:production` 预检脚本强制检查，缺失时退出码为 1。本地个人使用请用 `npm run dev`。正式部署请按「公网部署（单节点正式版）」和 [`docs/OPERATIONS.md`](docs/OPERATIONS.md) 配置 `.env`、Docker 与 nginx；未配置 `ZHIXU_PUBLIC_ORIGIN` 等必需生产变量时 `npm start` 会明确失败，而不是降级成无鉴权服务。开发与生产服务都使用 API 端口 3001，不要同时启动两份。

CI：`.github/workflows/ci.yml` 在 push 到 `main`/`master`、pull request 与手动触发时用 Node.js 22 运行 `npm ci`、`npm run check`、`npm test` 与 `npm run build`，不配置任何真实模型/搜索密钥，也不构建或启动 Docker。**本仓库开发机与 CI 都未实际执行 `docker compose build/up`、certbot 或 nginx**；`Dockerfile`、`docker-compose.yml`、`deploy/nginx.conf` 只有静态一致性测试，首次上线必须在目标主机按 [`docs/OPERATIONS.md`](docs/OPERATIONS.md) 第 13 节逐项验证。

## 学习方式

首页直接写「想学会什么，或解决什么问题」，基础可选；「学完希望能做什么」可展开补充实际用途，不是必填调查表。开始后，当前任务卡显示期望能力与正在学习的微概念。学习目标随会话保存在本机；服务端生成、评审与自动搜索查询都使用请求中的 `goal`（学习上下文里的 `learningGoal`），入口 `topic` 只是起点。明确切换主线时以当前目标带学，返回原主题时保留原任务。

「你来安排下一步」是显式领学操作：不发送伪造的“我懂了”，不把旧消息重新算作作答；导师可继续讲当前点，或在没有未处理困难/插问时进入相邻一个微概念，先前内容仍待核验。「我卡住了」请求补必要基础，「换个例子」「给点提示」辅助理解，「帮我复盘」区分讲过、已核验与未核验，并给下一次具体起点。可以先听或追问，不要求每轮交答案；只有真实独立表现才形成理解证据。操作期间保留未发送草稿，不能靠点按钮清误区、获得掌握认证或跳过整条路线。


- **无需模型的互动课程**：导数的直觉与应用、条件概率、Python 列表与循环。每门包含三节讲解、逐步提示、独立例子、理解检查、随堂练习和记忆卡。
- **导数实验**：拖动滑块，观察平方函数上的割线如何逼近切线。支持键盘 Home、End、方向键和重置。
- **AI 领学**：任意主题、基础程度、任务用途、学习路线、多轮追问、递进提示、换例子、复盘、练习和记忆卡。系统独立记录当前问题、理解证据、误区、临时插问与暂停主题。不会时补基础，质疑时校正前提，明确换目标时保存旧轨迹；路线位置与能力认证分开，既不靠手工勾选冒充掌握，也不把每轮作答作为听课门槛。
- **学习工作台与诊断**：首页可先做 3 题诊断确定起点；会话内工作台提供学习路径、迁移练习、真实错题/误区复习和学习报告，只归纳已保存的作答证据。详见下文「学习工作台」。
- **学习资料**：对话附件支持 UTF-8 `.txt` / `.md` / `.markdown`，单份上限120 KB、总文本上限60,000字符。整本书请使用「我的书架」，不要把长书当聊天附件。
- **笔记和复习**：收藏讲解、编辑 Markdown、渲染数学公式、练习判分与解析、翻转记忆卡、导出 Markdown。
- **学习足迹**：真实记录课程完成情况、知识笔记数量和近 35 天是否学习，不预填虚构进度。按 `N` 开启新学习，输入框和对话框中不会触发该快捷键。
- **书籍陪读**：本地导入 PDF 文本层、EPUB、UTF-8 TXT 与 Markdown，保留原文件、章节与段落。按章节阅读、章内搜索、长章分页、标记已读、摘录笔记；可从目录导览、章节或具体段落开始AI陪读与主动回忆，历史引文可回到原文位置。

### 带着一本书学习

1. 侧栏「我的书架」→「导入书籍」。文件在浏览器内解析，不支持解析的格式会在本地明确拒绝；不执行EPUB中的HTML脚本或加载外部图片。登录后，原文件与提取正文会按账号保存到服务端书架，用于跨设备；未登录时只保存在本机。
2. 选择章节阅读。EPUB按OPF spine正文顺序、文本按章节标题分节；PDF按可用一级书签分章，无书签则按文件页序分节。这里只提供提取后的文本阅读，不复刻原书版式、图表或图片。
3. 点击「陪我学这一章」「围绕此段学习」或「主动回忆」。本轮最多发送20段、24,000字符的真实原文；长章用具体段落入口选择范围，不静默把未提供部分当作已读。目录导览只发送目录与章节开头样本，不能冒充通读全书。
4. 讲解中的材料引文必须逐字来自本轮原文，位置由程序绑定；「回看原文」打开具体章节和段落。PDF位置注明文件页序，可用文档页标签不冒充印刷页码；EPUB以章节/段落定位，不伪造固定页码。
5. 阅读位置与「已读」只记阅读行为，不能认证掌握。摘录打开现有笔记编辑器，原文与「我的理解」分开；学习对话、练习、记忆卡和理解证据复用原有流程。

单文件最大30MiB，提取正文最多200万字符、1000节；超过时明确拒绝而非截断。损坏文件、缺失正文、加密/DRM会明确提示；纯扫描PDF没有文本层时需先在本机OCR，当前不内置OCR或解除加密。部分页无文本会显示范围警告。只导入自己有权使用的书籍；不联网搜书、不内置第三方书库。

提取文本可能规范化空白、换行和PDF文字顺序，复杂多栏、表格、公式或纯图片的内容需用原文件人工对照；逐字引文校验针对本轮实际提供的提取文本，不声称还原原书版式或保证OCR/排版准确。当前应用资源加载后可离线读已导入内容，不提供完整离线安装或首次离线启动支持。

方法参考 [`book-study`](https://github.com/sanyuan0704/sanyuan-skills/tree/main/skills/book-study) 的章节学习/独立应用与 [`ljg-book`](https://github.com/lijigang/ljg-skills/tree/master/skills/ljg-book) 的材料边界/论证脉络，已适配网页，不使用其Org/Emacs文件流程、强制反问或掌握百分比。PDF.js与fflate负责本地解析，不安装MinerU或调用云端OCR。来源及许可见 [`public/book-credits.txt`](public/book-credits.txt)，应用帮助页也可打开。

书籍学习功能的真实模型直连验收中，目录导览、段落陪读与新情境主动回忆均曾以两次模型调用完成，引文逐字匹配并可回跳；另有首轮超时与一次续聊上游响应无法解析。原文阅读与已有记录不依赖模型可用性，失败不会发布草稿或增加掌握证据；少量成功样本不代表稳定交付或事实认证。当时65项行为回归和生产构建通过，含既有47项教学状态/质检回归；页面验证覆盖EPUB、中文PDF、长章分页/搜索、刷新续读、原文件字节一致的下载、引用回跳、笔记/导出、离线已导入章节阅读、删书保留对话与存储禁用错误。

## 学习工作台

在任意学习会话中切到「学习工作台」（与「引导学习 / 随堂练习 / 记忆卡片」并列），四个子视图都只以已保存的真实数据为输入：

- **学习路径**：AI 主线按 `LearningState` 派生，「已完成」只认已保存的 `understood` / `applied` 理解状态；内置课程按 `completedStages` / `stageIndex` 显示理解检查进度，这些记录不等于推理或迁移证据。导师允许先听后续内容，所以“当前授课位置”和“前置已核验”分开显示；尚未核验的前置会标出，不能靠继续听课解锁或标成掌握。预计时间只是学习安排，不代表掌握。没有路线时明确要求先生成，不从旧聊天猜。
- **迁移练习**：围绕导师当前给出的迁移题作答；界面只展示真实待答任务与已有轨道，不预填题数或进度。提交时先取得真实评价，再核验 `LearningState.lastAssessment` 的题号与当前题一致、评价原话能在该步真实证据中逐字找到、证据类型达到本关门槛（同概念变式要推理，新情境/综合边界要迁移）；同题同类型的新作答更新对应证据，推理与迁移证据分别保留，较强证据不会被较弱回答覆盖。导师换题时替换尚未通过的当前关卡，不能把旧关补成完成；对不上就不推进、不新增掌握。只是请导师出题不算作答；内置课程没有 AI 学习主线时，此视图明确要求先建立主线，不把选择题冒充迁移证据。
- **复习**：只整理两处真实来源——已作答且答错的测验题，以及有导师实际修复讲解的误区。答对题不会新生成复习项；找不到对应真实讲解的误区宁可不生成。题面、当时的原话/错因和原解析随条目保留。按「忘了 / 模糊 / 会了」自评：忘了立即到期并清零连续次数，模糊 1 天后，会了按 1–3–7–14 天递增；到期与未到期分栏。「针对这个卡点补讲」用原题、已保存解析和你的原话单独请求模型，结果只作解释，不写回理解证据、不改复习调度，也不宣布掌握。侧栏「练习与复习」会跨会话汇总同一批复习项。
- **学习报告**：有 AI 学习状态时，汇总真实作答证据（辨认 / 推理 / 迁移）、未核验内容、开放误区、到期复习与下一步入口；没有证据的地方写明「未核验」，不生成虚构百分比。只有课程理解检查时明确说明它不等于推理或迁移证据。

**首页诊断**：在首页输入主题后点「先做诊断，找合适起点」，由当前配置的模型生成 3 道诊断选择题并进入工作台。提交后逐题给出薄弱概念、识别正确但「仍需推理核验」的内容和推荐进入点；内置课程可回到推荐小节，AI 路线会让导师从推荐起点开讲。诊断只用于安排起点，选择题点击不是理解证据，也不能认证掌握；生成诊断需要先配置模型，题目可能超时或出错，需自行核对。

## 教学质量与能力边界

一次 AI 回合先生成聚焦的讲解（问题可省略），再发起**独立角色的语义评审请求**；程序负责绑定问题身份、核对真实证据并原子提交状态，不要求生成模型重复整套学习状态。通常调用模型两次（草稿 + 评审）；未配置独立评审模型时最多一次写作修订，配置独立评审模型后最多两次，加上评审自身格式修复（最多两次），单次回合硬上限为 **6 次模型调用**（`MAX_MODEL_CALLS`），超出直接失败而不是降低质检。若只是评审自身格式错误，只补小型评审，不盲目重写讲解。单次回合上限150秒，单次模型请求默认最多60秒（`AI_MODEL_CALL_TIMEOUT_MS` 可调 10–120 秒）且不能超过整轮剩余时间；前端165秒等待上限不变，不额外自动重试，超时、取消、认证或网络失败不以虚构回答兜底。模型故障转移会让下一个候选模型重新执行整轮；前端 165 秒总等待仍会中止超出部分。

未过门槛的草稿不作为助手回复发布，不提交新的学习状态。评审缺字段、自称通过但检查不一致、重做原题冒充迁移、虚构回答证据等都会被拒绝。旧会话和笔记继续保留，旧的自评勾选不会迁移成理解证据；从下一轮开始建立可核验状态。

按钮动作的本轮操作意图在完整聊天之后单独传给生成模型，不能继续回应旧问题来冒充复盘。普通回合评审当前焦点；复盘额外提供按原顺序保留的完整对话，以核对“实际讲过什么”。这不把旧聊天变成新的作答，也不认证讲过的内容已经学会。复盘/练习/卡片评审使用工具协议，不返回知识判定或导航决定。
复盘正文的“已核验/已掌握”不能替代结构化理解证据；没有已记录证据时，服务端会要求复盘改为未核验，工具动作仍原样保留既有学习状态。评审或模型回合失败时不提交掌握状态，下一轮可在保留原话的基础上重试。
422后若学习者改写未获回复的回答，服务端只在发给模型的请求上下文中标记旧输入，不改写本地聊天记录或导出内容；最后一条用户输入仍是本轮唯一作答。复盘按步骤的mastery和证据核对已核验/未核验，不因其它步骤已有证据而替当前步骤认证掌握。
失败的用户回合会在聊天中标记为“未获导师回复”，提供原样重试和改写后重试；重试不会伪造助手消息或把失败回合写入理解证据，导出记录保留失败标记。后续已有助手回复时，旧失败回合只保留为历史，不再提供重试按钮；同一失败回答的再次提交复用原消息身份，不复制用户消息或理解证据。

AI领学主流程当时的验收为 93 项行为回归、TypeScript 检查与生产构建通过；真实模型已跑通目标开学、先讲不出题、主动安排下一步、卡住后补基础及复盘。最终复盘分开讲过/未核验/下次起点，再点击继续听讲仍无伪造作答或掌握证据。手机390px无横向溢出，五个领学操作为44px高，刷新可续学；已复现并修复底栏遮挡与失败覆盖未发送草稿。验收也出现多次超时、上游响应无法解析、质检拒绝，以及HTTP 200但业务表述过度泛化、未真正执行复盘的样本：已补充状态推论边界、明确本轮操作优先于旧聊天、为复盘评审提供完整对话，但这些约束不保证模型不再犯错。不要把成功发布率当教学正确率。

无歧义的字段误嵌套、唯一误区说明对象、前提的角色标签与原文、正文中独立重复的结构化题面，可由程序安全整理并留下回执，不增加模型调用；两处内容冲突、对象含其它事实字段或语义不明确时不会自动猜测。原生 JSON 只降低格式错误，不替代语义评审。

私有判定中的数字结果同样适用于带计算任务的推理题，不能靠误标题型绕过保护。新问题的结果若已在正文出现，会在付费语义评审前拦截并要求修订；这是字面结果保护，不能代替数学推理或事实核验。

旧聊天不等于已有结构化主线：首次建档显式提示生成路线，不把旧题直接认证为掌握；已知缺路线与抢答问题在同一次预检中汇总。导师应先讲术语、机制和例子，允许公式与中间步骤，不以防抄答案为由让零基础学生盲猜。正文中独立重复的结构化题面会在安全可识别为题块时整理并只保留结构化问题；含解释或语义不明确时仍要求修订。

模型生成的“建议答案/建议回复”不作为可点击作答发布；否则点选模型写好的完整答案可能被错记为学习者理解。学习者需要自己表达原理；知识选择题最多产生辨认证据，方向选择只是偏好。

**授课位置不等于掌握认证。** 答对知识选项后可以继续相邻的小概念，学习者也可明确选择先往下讲；旧概念仍待核验，不会自动升级为“已解释”。答错、不会或质疑时先处理当前困难。首错不得在正文、下一问、反馈或误区中抢先公布未解出的结果；明确索要完整答案时可以讲解，但请求本身不算独立掌握证据。

评审请求仍使用当前配置的模型，并不是一个保证正确的外部裁判。同一弱模型可能连续犯相同的事实错误；自动搜索只在配置了搜索供应商时提供网页摘要线索，不等于事实或法规核验能力。**教学流程检查通过不等于事实认证，也无法保证任意模型达到 Gemini 的知识与推理水平。** 产品参数、监管时效等需核对可靠材料；用户上传的旧对话只作学习素材，不被当成权威真值。

工作台沿用同一证据边界：诊断只排起点，自动整理的复习项必须有真实错题或真实修复讲解，迁移推进必须让 `lastAssessment` 与已保存证据对齐；补讲和报告是解释与汇总，不是新的掌握认证。当前版本的真实模型直连中，首页诊断题生成与复习补讲都曾成功返回；质量门禁和结构校验只保证流程可执行，不等于内容事实正确、每次调用可用，也不构成 UI 人工验收。

### 教学词汇

- **理解证据**：学习者针对具体问题的真实原话，连同当时的问题与证据类型；不是模型自己的讲解，也不是“我懂了”或点击提示。
- **已解释**：本轮真实作答展示了该概念的推理；不代表整块业务领域已掌握。
- **迁移通过**：已有独立解释证据，并在另一道改变情境的问题中正确应用。原题换编号、同题复述、单选猜中不能晋级为迁移通过。
- **误区**：有本轮错误或部分正确回答支持的具体理解偏差；听过解释不会自动消除，需在另一道同概念迁移题中重新核验。
- **临时插问**：暂离主线但保留返回点的讨论；补课中的证据不替代原主线进度。
- **暂停主线**：明确换目标时保存的步骤、证据、误区、原问题与前提；回到同名目标时恢复，而不是从零猜测。当前最多保存八条暂停主线与五层嵌套插问，超限会明确提示拆分会话，不静默丢弃。
- **材料引文**：逐字匹配所附同名材料的摘录，仅说明材料依据，不说明材料权威、准确或最新。
- **数值证据闸门**：计算题若带私有数值答案，程序会核对学习者本轮是否包含全部目标数值；未命中时不得判为正确，也不得记为推理/迁移证据或已掌握。该闸门是字面数值核对，不做符号推导，不能替代完整数学评分。

`npm test` 使用自包含业务情景与受控调用器，验证状态转移、错误拒绝、调用上限、取消、超时及密钥隔离；这些测试不能替代真实模型教学质量评测。原始 Gemini 记录未作为默认课程或真值表捆绑发布。

公网单节点版本的最终工程验收为 577 项回归、TypeScript 检查和生产构建全部通过；真实生产页面已验证注册、恢复码换密与轮换、登录恢复、两账户隔离、课程/笔记云端同步、暂停同步循环、无变更不写 revision、云笔记删除刷新不复活、删除账户后会话失效。独立 HTTP 会话已验证跨设备书籍恢复：同账户第二会话取回 1 本云端书，下载原文件字节、SHA-256 与响应头完全一致；清空本机书架缓存后，云端书目仍可列出并按需下载进入阅读。匿名本地书架首次登录会后台迁移，持久迁移台账防止已删除书被匿名副本复活。正式模型已接入；优化后完整 6 项真实发布门禁连续两轮 6/6 通过，跨学科套件（9 场景、11 回合）连续两轮 9/9 通过，均为 0 超时、0 供应商错误；这些是固定剧本结果，不等于所有主题或长期稳定性都已通过验证。

本轮优化定位并修复了四类问题：单模型复审的思维链无限膨胀导致超时、评审返回无效 JSON、真实作答缺少结构化判定、数值错误被误记为推理证据。修复方式是独立评审模型、评审 `temperature=0`、授课 `temperature=0.4`、有界的评审/修订重试，以及计算题的程序化数值闸门；没有关闭质检、硬编码业务题答案或隐藏拒绝。失败时仍不发布草稿、不改变学习进度。

## 接入真实模型

### 网页内配置

必须先登录且部署开启 BYOK（公共模式需 `ZHIXU_ALLOW_BYOK=true`；本地开发默认允许），才能在「模型与设置」中填写个人 API 密钥；未登录页面不会渲染个人模型/搜索密钥输入框，服务端也会拒绝未登录请求携带的请求内密钥。

登录后可以配置两类个人密钥：

- **模型**：Gemini 或 OpenAI 兼容服务，填写密钥、模型名称与兼容接口地址；主模型 Key 必填，未配置时模型请求会被明确拒绝，不会回退服务端共享 Key。可添加最多 2 个备用模型（主配置 + 备用共 3 个），备用模型 Key 需单独填写，留空不生效。切换模型服务商会清空主模型已填写的密钥，但保留已填写的接口地址；只有接口地址为空时才填入官方默认值。
- **搜索**：可选 Tavily、Brave、Exa、Firecrawl、DeepSeek 或 You.com；可添加最多 5 个备用搜索供应商。搜索 Key 仅在发起联网搜索时需要，不启用联网搜索时无需配置。You.com 允许留空 Key 使用免费接口，其它供应商空 Key 视为未配置。切换搜索供应商会清空主搜索已填写的密钥。

主模型遇到认证（401/403）、限流（429）、连接/超时与 5xx 时，会按顺序切换备用模型；其它 4xx（如 400/404 参数或端点错误）、教学质量拒绝或整轮 150 秒超时不切换，避免掩盖内容问题或放大延迟。故障转移会让下一个候选模型重新执行整轮；响应 `quality` 中的 `model` 记录实际完成本轮的模型名，`fallback` 标记是否发生切换。搜索会按主配置、备用配置顺序尝试，前一供应商失败或没有结果时继续下一个。主模型、主搜索以及备用模型/搜索的配置和 Key 在登录后加密保存到服务端 SQLite（每账户一行），只有当前账户可读取；清除浏览器数据不会丢失，重新登录后自动恢复。删除账户会级联删除。它们不写入日志、学习备份或云端工作区。**登录且开启 BYOK 时，模型与搜索请求只使用该账户保存的个人 Key（含主配置与备用配置）；未配置个人模型 Key，或请求联网搜索但没有可用个人搜索配置时会被明确拒绝（409），绝不回退服务端共享 Key。唯一例外是搜索显式选择 You.com：它允许留空 Key 使用免费接口。**

兼容服务填写包含 `/v1` 的基础地址；`https://api.openai.com/v1` 是官方 OpenAI 端点，始终允许。第三方兼容端点必须是管理员在 `ZHIXU_BYOK_BASEURLS` 登记的 origin，否则保存或请求返回 403 `byok_endpoint_not_allowed`。HTTP 仅允许 `http://localhost` / `127.0.0.1` / `[::1]`，且该 origin 同样要先登记；服务端 `.env` 的 `OPENAI_BASE_URL` 属于运维可信配置，不受个人端点白名单限制（本机端点走这条服务端路径）。

网页内填写的个人模型/搜索配置与 Key（含主配置和备用配置）在登录后加密保存到服务端 `user_credentials` 表，每账户一行；只有该账户登录后可读取。它们不进入云端工作区、学习记录、导出或 JSON 备份，也不写入日志。清除浏览器数据不会删除服务端凭据；重新登录后自动恢复。发起请求时经本地 API 服务转发；个人搜索密钥只用于该登录用户的当次搜索，不会使用其他用户的密钥；发起联网搜索但没有可用个人搜索配置时不会回退服务端共享 Key（显式选择 You.com 的免费接口除外）。应用配置不代表密钥已经通过验证，首次发送问题或搜索才会实际调用。

默认开启「原生 JSON 输出」：Gemini 使用 `responseMimeType`，OpenAI 兼容服务使用 `response_format`。若兼容服务明确不支持，可取消勾选后手动重试；不会自动重试降级或关闭质量检查。切换服务时保留本页选择。
「思考等级」支持自动、低、中、高。Gemini 已知模型族映射为 `thinkingLevel` 或 `thinkingBudget`；OpenAI / 兼容服务映射为 `reasoning_effort`。自动不发送额外参数；未知 Gemini 模型、GLM-5.3 的中档等不支持的组合会在请求前明确报错，其他上游参数拒绝会提示调回「自动」，不会静默降级或关闭教学质检。GLM-5.2/5.3 按官方文档同时启用 `thinking.type=enabled` 并发送强度；GLM-4.x/5/5.1 官方不支持 `reasoning_effort`，指定低/中/高会明确拒绝。GLM 的开关、强度预算和关闭能力不通用，不能仅靠模型名称包含 `glm` 推断兼容。

### 服务端配置

本地开发不要复制整份 `.env.example`（那是生产部署模板，会强制登录并禁用个人 Key）。在项目根目录新建 `.env`，只需填写 `GEMINI_API_KEY` 或 `OPENAI_API_KEY`（按所选服务二选一）及对应模型配置，其余保持默认：

- Gemini：`GEMINI_API_KEY`、`GEMINI_MODEL`，默认模型 `gemini-2.5-flash`。
- OpenAI 兼容：`OPENAI_API_KEY`、`OPENAI_MODEL`、`OPENAI_BASE_URL`，默认模型 `gpt-4o-mini`。

`ZHIXU_AUTH_REQUIRED`、`ZHIXU_ALLOW_BYOK`、`ZHIXU_PUBLIC_ORIGIN` 等生产项保持未设置，本地 `npm run dev` 才不会要求登录，并保留网页内个人 Key 输入。生产部署再参考 `.env.example` 的完整模板。

两种密钥同时存在时优先 Gemini；网页临时配置有密钥时优先网页配置。修改环境变量后重启服务。模型名称可按供应商当前可用列表调整。

使用后端密钥时，`AI_STRUCTURED_OUTPUT=false` 可关闭原生 JSON 参数，默认开启；修改后重启服务。网页有临时密钥时采用网页的开关；无临时密钥则采用后端配置。
服务端可用 `AI_THINKING_LEVEL=auto|low|medium|high` 设置默认等级；网页临时配置有 API 密钥时优先网页设置。思考等级会影响耗时、费用和输出稳定性，不等于事实正确性或掌握认证。

服务端可设置 `AI_REVIEW_MODEL`，在同一提供方端点上启用独立评审模型；留空时仍由授课模型自评。独立评审模型只用于 review 调用，授课仍由 `OPENAI_MODEL` / `GEMINI_MODEL` 完成；它使用同一端点与密钥，不新增第三方接收方。网页临时密钥（BYOK）请求不会启用服务端评审模型，避免把用户密钥转交给额外模型。未配置或评审模型与授课模型同名时，单模型流程和一次修订上限保持不变。`AI_REVIEW_THINKING_LEVEL` 控制评审思考等级，默认 `auto`。

`AI_MODEL_CALL_TIMEOUT_MS` 控制单次模型请求上限（默认 60 秒，可设 10–120 秒；单次教学回合仍受 150 秒约束，故障转移会给下一个候选模型重新计时，前端 165 秒总等待是实际中止点）；`AI_MAX_OUTPUT_TOKENS` 控制 OpenAI 兼容模型的输出上限（默认 8192，Gemini 不套用，避免截断思考预算）。两者用于防止无界生成拖死整轮，不改变教学质检。排查延迟时可设 `AI_DEBUG_TIMING=true`，日志只记录调用目的、耗时、token/字符数，不记录提示、回答或密钥；正常运行时保持关闭。

无密钥时可以完整学习预置课程；自由问答会提示连接模型，不会用预置文本冒充 AI 回答。真实云端可用性、费用、速度、上下文容量和教学质量取决于供应商及所选模型。

当前本机正式教学模型为 OpenAI 兼容端点 `http://127.0.0.1:3425/v1` 上的 `wb/cn:deepseek-v4.1-flash`，密钥只写在服务端 `.env`。该端点必须从运行 Node 服务的主机可达；Docker/远程部署时应换用容器可访问的地址或同宿主网络，不能把 `127.0.0.1` 当成远端地址。

正式模型接入实测：端点探活返回 200；应用真实 `/api/chat` 返回 200。授课模型为 `wb/cn:deepseek-v4.1-flash`，同一本机端点上的 `wb/cn:glm-5.3-flash` 只做独立评审。优化后完整 6 项门禁连续两轮 6/6 通过，0 超时、0 供应商错误；两轮总耗时约 170–193 秒，单个最慢用例 84 秒，低于 150 秒整轮上限。此前 2/6、3/6、5/6 的失败已分别定位为上游超时、评审 JSON/判定不合约、数值错误被误认证，并在不放松门禁的前提下修复。门禁是固定剧本，不能据此宣称所有主题或长期运行都稳定达到目标产品。

### 跨学科泛化评测

`npm run eval:teaching:broad` 使用独立套件 `eval/teaching-suite-broad.json`，覆盖 7 个主题、9 个真实模型场景、11 个回合：

- 数学：一元二次方程开场路线。
- 编程：Python `range` 首错修复与误区留证。
- 编程多回合：明确题外插问保存返回点，恢复原题后再作答。
- 物理：速度计算错误被数值闸门拦截，以及正确数值被接受。
- 英语：一般现在时选择题只认证辨认。
- 生物：光合作用复盘区分讲过与未核验。
- 经济：通货膨胀错误前提按真实作答纠正，不泄露方向结论。
- 历史：工业革命开场建立多维解释路线。

最近连续两轮完整跨学科评测均为 **9/9 通过、0 错误**，单轮约 3 分钟，最慢单例约 38 秒。多回合场景额外验证：明确插问必须保存原步骤与原题，恢复时必须回到原题号；服务端以保存的返回点为准，模型在恢复时另出新题会被覆盖，不能丢失原题。该套件仍使用固定剧本，不等于任意主题都能一次通过；它提供的是跨学科结构约束的重复抽样证据，而不是全面教学质量认证。

跨学科审计还发现并修复了：4096 token 会截断部分数学开场、错误作答被评审标成 `continue/challenge`、计算题可以用非数值说明冒充私有答案、带单位的数值答案被结构检查误拒、“已核验什么”这类疑问式复盘标题被误判为掌握声明，以及插问返回点在恢复时被新题覆盖或答案泄露。

### 自动联网搜索与指定网页来源核验

`ZHIXU_WEB_FETCH` 与 `ZHIXU_WEB_SEARCH` 相互独立：`ZHIXU_WEB_FETCH=true` 只开放指定 URL 的「添加网页资料」抓取；`ZHIXU_WEB_SEARCH=true` 开放服务端搜索供应商链。未设置 `ZHIXU_SEARCH_ORDER` 时，服务端默认按内置顺序（You.com 在链首）尝试；You.com 免费接口无需 Key，因此只开启开关即可先使用免费搜索（受第三方额度、网络和可用性影响）。自动搜索按钮的可见性按当前身份判定：未登录或未启用个人密钥时看部署是否开启 `ZHIXU_WEB_SEARCH`；登录且开启 BYOK 时只看该账户保存的个人搜索配置（显式选择 You.com 可免 Key），不会用服务端搜索兜底。两项开关互不依赖；书籍陪读模式不并发自动搜索。实现参考 Magpie 的 `search_api` 供应商链，但由本应用独立实现，不调用 Magpie 运行时。

自动搜索支持的供应商（按 `ZHIXU_SEARCH_ORDER` 顺序尝试）：

- `you`：无 Key 的 You.com 免费接口（受第三方额度、网络和可用性影响）；未设置 `ZHIXU_SEARCH_ORDER` 时默认排在链首。服务端链和个人配置都支持留空 Key，其它供应商空 Key 视为未配置。
- `tavily`、`brave`、`exa`、`firecrawl`、`deepseek`：填写对应 key 后启用。
- `searxng`：填写 `SEARXNG_URL` 后启用。

搜索结果是**搜索摘要片段**（`search_snippet`），不是页面全文；模型只能引用片段中逐字存在的文字。它的价值是发现来源，不是事实认证。来源卡片会显示 URL、抓取时间、搜索摘要/页面抓取状态，以及按域名启发式计算的来源等级（官方/教育域名、一手资料、二手资料、未分级）。多来源冲突、来源不足或摘要不支持结论时，评审应要求并列说明或标未核验。

「添加网页资料」则是指定 URL 的完整网页抓取，可选择一段原文做逐字命中核验。两种能力都不会保证网页权威、内容正确、条件完整或仍然最新。

安全边界：只允许 HTTPS 默认端口和公开 DNS 地址；拒绝 localhost、内网、链路本地、保留地址、URL 凭据和未知端口；校验重定向目标；限制响应大小、正文长度、抓取超时和每用户每小时请求数。`ZHIXU_WEB_ALLOWED_HOSTS` 可进一步限制允许域名，公网部署建议设置。

搜索供应商链的灵感来自 [Magpie](https://github.com/yetone/magpie) 的 `internal/gateway/search_api.go`（MIT）；本应用没有直接调用 Magpie MCP，也没有把搜索摘要当作已认证事实。

## 数据与隐私

- 学习会话、答题结果、记忆卡状态、笔记和活动记录默认存于**当前浏览器、当前网站来源**的 localStorage，支持同来源标签页更新同步。未登录（包括本机模式下未登录）时没有个人账户数据、云端备份或跨设备同步。AI 请求按会话使用浏览器 Web Locks 互斥；同一会话另一标签页正在生成时，新请求会明确拒绝。会话消息按 ID 合并，路线与工具产物采用较新的快照；普通笔记删除及同一字段的同时修改仍应避免多标签页并发编辑。登录公网版账号后，本机记录与该账户云端工作区双向合并（冲突时重取云端后只重试一次）；切换账户或检测到没有归属标记的旧记录时，只载入该账户云端快照，旧记录另存本机备份键、不并进新账户。见下文「公网部署（单节点正式版）」。
- 损坏或旧格式记录在首次加载时不会被空数组覆盖；首次修改前会要求确认替换。该保护不是自动修复或格式迁移，原始内容应先导出备份。
- 书架在本机用同来源 **IndexedDB** 缓存原文件、提取正文与阅读进度。登录账户后，原文件和提取正文另按账号保存到服务端书架，单本原文件上限 30 MiB、元数据 8 MiB，每账户最多 100 本/500 MiB，用于跨设备恢复；阅读进度与已读标记仍只在本机，不虚构跨设备进度。清理浏览器数据会清除本机缓存，但可从账号书架重新下载；退出或换账户不会看到其他人的书架。会话只保存原文位置标识，发送AI时按所选段落从书架读取；公开讲解中的短引文与摘录笔记仍随学习记录保存。
- 清理浏览器数据、更换浏览器或切换网站端口，会使旧记录不可见。重要内容请及时导出。
- **JSON 学习数据备份**：登录后使用顶栏下载按钮导出 `zhixu-study-backup` v1 JSON，包含会话（路线、讲解、对话、练习、记忆卡、理解证据、误区、迁移轨道与诊断）、笔记、笔记删除墓碑（`deletedNoteIds`）、复习项、诊断、学习活动日期（首页展示近 35 天），以及服务商 / 模型名 / 基础地址 / 思考等级等非敏感设置。**不含 API 密钥、书架原文件、提取正文或阅读进度**，也不会把整本原书打进文件。未登录时点击备份入口会打开登录/注册面板，不会下载或选择文件。
- **导入是合并，不是替换**：登录后使用顶栏上传按钮校验并合并——同 ID 会话按消息 ID 与较新快照合并，双方对话增量尽量保留；同 ID 笔记、复习项和诊断按可证明的版本取较新者（笔记只认严格更新的 `updatedAt`；复习项按 `updatedAt` → `attempts` → `dueAt` → 是否已评分；诊断已提交优先，双方已提交时只认严格更大的 `evaluatedAt`），无法证明更新时保留当前记录；活动日期取并集；非敏感模型设置也只在备份的 `settingsUpdatedAt` 严格更新时才覆盖当前设置。笔记删除墓碑取双方并集，已删笔记不会因导入复活。个人 Key 由服务端按账户独立保存，不进入备份，也不会被导入替换。备份始终不含密钥。含 `apiKey` / `secret` 等敏感字段、结构不合法、重复 ID 或超过 20 MB 的文件会被拒绝，失败不会覆盖现有数据。未登录时不会打开文件选择器。
- **Markdown 只供阅读**：会话内「导出学习记录」生成讲解、对话、理解证据、记忆卡等 Markdown，练习解析仅在已交卷时写入；笔记也可单独或全部导出。不会把整本原书打进 Markdown，且 Markdown 不能重新导入恢复学习状态。登录状态删书先删除账号云端书目，再删除本机原文件、正文和阅读进度；不删除已有学习对话和笔记，重新导入同一原文件后可再次回看出处。
- 部署开启 BYOK（`ZHIXU_ALLOW_BYOK=true`）时，网页内填写的个人模型/搜索配置与 Key（含主配置和备用配置）在登录后加密保存到服务端 `user_credentials` 表，每账户一行，只有该账户可读取；清除浏览器数据不影响服务端凭据。登录后模型 Key 必填，搜索 Key 仅在联网搜索时需要（You.com 可留空），未配置所需 Key 的请求会被拒绝，不会回退服务端共享 Key。它们不写入云端工作区、学习记录或 JSON 备份；服务端密钥来自 `.env`，由服务端读取。未登录请求携带的请求内密钥会被服务端拒绝。
- AI 模式会向选择的模型服务发送完整的当前对话、所附资料和相关学习状态；内置课程学习本身不调用模型。请勿上传隐私或敏感内容。
- API 有输入限额、超时、上游错误提示和输出结构校验；不自动截断用户对话。模型输出仍可能存在事实错误，应核对可靠来源。
- 服务默认只监听本机，并限制本地网页来源；本机模式下它不是带鉴权的公网多用户服务。公网部署需启用「公网部署（单节点正式版）」章节描述的账号认证、额度、可信来源与 TLS 反向代理，单节点边界见该章节。

## 公网部署（单节点正式版）

除本机单人使用外，知序可以作为**单节点公网多用户服务**部署：账号登录（邮箱 + 密码，scrypt 加盐哈希，会话与恢复码只存哈希）、Cookie 会话（HttpOnly + SameSite=Strict，生产默认 Secure）、服务端保存的学习工作区（`StudyBackup` v1，按用户隔离，`revision` 乐观并发）、每用户每日模型调用额度。

- **单节点边界**：官方支持的是一个进程 + 一个 SQLite 数据库。不要开第二个写实例、不要把数据目录挂到共享卷横向扩展；官方部署假设没有多实例并发。容量靠纵向扩容与备份。
- **反向代理**：TLS 必须由反向代理终止，`ZHIXU_TRUST_PROXY=true` 是正式部署必需项；否则所有用户共用代理 IP 的登录限流桶。生产配置还会拒绝 HTTP 公网来源和不安全 Cookie。
- **公共模式**：`--production` 或 `ZHIXU_AUTH_REQUIRED=true`。聊天、诊断、复习补讲必须登录；默认只使用服务端环境密钥。开启 `ZHIXU_ALLOW_BYOK=true` 后，用户需先在「模型与设置」中保存个人 Key，之后请求会使用该账户已保存的个人配置；未保存所需 Key 时返回 409，不会回退服务端共享 Key，也不使用请求内临时密钥。
- **额度与并发**：chat / diagnostic / review 按 UTC 日期每用户持久化，默认 40 / 10 / 30，环境变量可配；同一用户默认最多 2 个在途 AI 请求，超限返回 429 与重置时间。并发闸门是单进程保护，与单节点限制一致。
- **账号与同意**：注册需显式勾选服务条款与隐私说明；恢复码只在注册或重置密码后显示一次。发布前必须由法律顾问审阅 `public/terms.html` / `public/privacy.html` 并填写运营主体。
- **部署物**：`Dockerfile`（多阶段、非 root、HEALTHCHECK、/data 卷）、`docker-compose.yml`（应用 + nginx，单节点）、`deploy/nginx.conf`（TLS、HSTS、请求体限制、静态缓存与 API 分离）、`.env.example`（全部生产变量，密钥留空）。
- **数据库结构**：SQLite `PRAGMA user_version = 4`（`users` / `sessions` / `recovery_codes` / `workspaces` / `daily_usage` / `audit_log` / `auth_rate_limit` / `library_books` / `library_originals` / `library_deletions` / `user_credentials`）。迁移只追加、启动时执行；版本或必需表不一致会直接拒绝启动，不做静默降级。
- **部署前检查**：`npm run check:production` 校验 https 域名、Cookie Secure、反向代理信任、数据目录可写与模型密钥来源，给出中文诊断；有阻断问题时退出码为 1，通过时为 0，提醒项需人工确认。
- **备份**：`npm run backup:db` 用 SQLite `VACUUM INTO` 生成带时间戳的一致性快照并做 `integrity_check` 校验；同一次运行产出三件套：`zhixu-<stamp>.db`、`zhixu-<stamp>.credentials.key`（存在 `credentials.key` 时复制）与 `zhixu-<stamp>.manifest.json`（记录数据库/密钥的 SHA-256、字节数、凭据行数与配套关系）。数据库快照、密钥副本与 manifest 权限均收紧为 0600，输出目录收紧为 0700。数据库已有加密凭据但密钥缺失或损坏时拒绝生成备份；默认保留最近 14 份，按 stamp 成组清理。恢复步骤见 [`docs/OPERATIONS.md`](docs/OPERATIONS.md)，不提供一键覆盖生产库的脚本。
- **运维手册**：[`docs/OPERATIONS.md`](docs/OPERATIONS.md) 覆盖首次部署、HTTPS、备份恢复、日志监控、配额、密钥轮换、数据删除、事故响应与上线验收。
- **法务页面**：`public/privacy.html` 与 `public/terms.html` 是中文模板，覆盖数据处理、模型供应商、浏览器存储、账号删除与恢复码。发布前必须由法律顾问审阅，页面本身声明不构成合规认证。
- **账号数据同步**：登录后学习会话、笔记、复习项与诊断保存在服务端工作区，登录设备间同步。冲突写入返回 409，客户端重取云端、双向合并后只重试一次，不静默覆盖（合并规则与导入一致）。笔记删除先写服务端墓碑：`POST /api/workspace/note-delete` 把 `deletedNoteIds` 与笔记移除原子落盘并推进 `revision`；旧设备或旧云端快照若重新带回已删笔记会返回 409 `note_tombstoned`，墓碑随工作区持久化，不依赖本机缓存。非敏感模型设置带更新时间，较旧版本不会覆盖较新版本。书籍原文件与提取正文按账户保存到服务端书架；另一设备列表只取云端摘要，打开某本书时才拉取元数据与原文件（按需懒加载），服务端按 1 MiB 分块读取并以流式响应发送，客户端校验字节数与 SHA-256 后才写入本机 IndexedDB。本机 IndexedDB 仍按账号隔离，换账户看不到他人书架，删除账户级联清理服务端与本机书架。阅读进度只在本机。
- **验证边界**：仓库开发机与 CI 都未执行 Docker build/up、certbot 或 nginx；`tests/deployment-config.test.ts` 只做静态一致性检查。首次上线必须在目标主机按 [`docs/OPERATIONS.md`](docs/OPERATIONS.md) 第 13 节逐项验证；真实模型评测需另配供应商密钥运行 `npm run eval:teaching`，不能由 CI 绿灯替代。
- **发布门禁**：`npm run eval:teaching -- --list` 可检查教学套件；配置真实供应商密钥后运行 `npm run eval:teaching`。它用程序独立核对结构化状态、题号身份、逐字证据、答案泄露和数值结果。退出码 2/3 分别表示未配置或供应商失败，均不能视为通过；离线回归通过也不能替代真实模型评测。

## 代码结构

- `src/App.tsx`：应用外壳、学习流程与工作台视图聚合。
- `src/components/StudyTools.tsx`：模型配置、练习和记忆卡。
- `src/components/LearningProgress.tsx`：桌面/手机理解证据、误区、主线恢复及教学检查回执。
- `src/components/DiagnosticPanel.tsx` / `LearningPath.tsx` / `TransferPractice.tsx` / `ReviewWorkspace.tsx` / `LearningReport.tsx`：诊断表单及工作台的路径、迁移、复习、报告子视图。
- `src/components/RichText.tsx` / `MarkdownContent.tsx`：按需加载 Markdown 与数学排版；KaTeX 升级到 0.18（`package.json` 依赖 `^0.18.2`，用 `overrides` 统一版本，当前锁定 0.18.11），首页不加载数学渲染依赖。
- `src/components/LazyBookLibrary.tsx` / `LazyDerivativeLab.tsx` / `vite.config.ts`：书架与导数实验只在各自视图动态 `import()`，`manualChunks` 只拆 React 运行时，KaTeX、PDF.js 与图标保持自然分包。
- `src/components/DerivativeLab.tsx`：可交互的导数图解。
- `src/lib/courses.ts`：预置课程内容。
- `src/lib/storage.ts`：本地持久化、标签页同步与导出。
- `src/lib/learningState.ts`：浏览器与服务端共享的学习状态协议；校验步骤、证据、误区、迁移与暂停主线，拒绝无证据的掌握升级。
- `src/lib/diagnostic.ts` / `learningPath.ts` / `transfer.ts`：诊断评分与起点、路径依赖/进度、迁移关卡与证据门槛。
- `src/lib/review.ts` / `backup.ts` / `settings.ts` / `sessionMerge.ts`：错题/误区复习调度、备份校验与合并、非敏感配置和密钥隔离、会话合并。
- `src/bookTypes.ts` / `src/lib/bookImport.ts`：书籍章节/段落/位置契约，浏览器内PDF/EPUB/文本解析。
- `src/lib/bookStorage.ts` / `src/lib/cloudBooks.ts` / `src/lib/bookStudy.ts`：账号隔离 IndexedDB 书架、云端书目/原文件同步、阅读位置和有界原文学习范围。
- `src/components/BookLibrary.tsx`：书架、章节阅读、定位回跳与摘录入口。
- `server/library.ts` / `server/books.ts`：账号级云端书架存储与配额、书籍教学策略、覆盖范围校验与可信引文位置绑定。
- `server/diagnostic.ts`：诊断出题与复习补讲；两者独立于主线回合，不写入理解证据。
- `server/ai.ts`：真实 Gemini / OpenAI 兼容模型适配、主/备模型故障转移与密钥隔离；官方 OpenAI 端点为默认值，第三方端点受 BYOK 白名单限制。
- `server/tutor.ts`：生成、独立评审、有界修订（单模型 1 次 / 独立评审 2 次）、6 次调用预算、取消与超时的有界编排。
- `server/credentials.ts` / `server/credentialVault.ts`：按账户加密保存个人模型/搜索配置（主配置与备用配置），加密密钥为 `credentials.key`；缺 key 或密文不自洽时拒绝写入新密文。
- `server/learning.ts`：学习状态、原话证据、误区修复与主线切换的确定性政策。
- `server/protocol.ts`：轻量讲解、独立评审、无歧义整理与身份绑定。
- `server/answers.ts`：私有结果标记与数值格式归一化，辅助拦截过早抢答。
- `server/workspace.ts` / `server/db.ts`：工作区 revision 乐观并发、笔记删除墓碑与旧快照复活拦截、SQLite 迁移（当前 v4）；书架原文件按 1 MiB 分块读取。
- `tests/`：50 个测试文件，覆盖教学状态、诊断、复习调度、迁移、备份合并、云端同步、书籍、个人凭据、配额并发、前端懒加载与部署静态配置，不依赖真实供应商。
- `server/index.ts`：API、来源检查和生产静态托管。

项目的 `.omp/agents/` 目录是本地开发用的子代理配置，不随开源仓库发布；应用内学习模型（Gemini / OpenAI 兼容）在「模型与设置」中自行配置。
